## 三、已知限制（不阻塞，登记在案）

1. **runtime.session 仍是进程级**：`new_session` 在 store 建了新行，但 runtime 自身的 `this.session` 不切换。UI 切了 activeSessionId 后新任务会归到新 session（sessionId override 已通），但 `task.clarified` 等早期事件的 sessionId 仍是新 id——正确。
2. **SSE 重连后 bootstrap 会重发**：switchSession 重新 start 会推新 bootstrap，UI store 会用新 sessions 列表覆盖。
3. **select_provider 不持久化**：切换只改 fallback 游标，重启后回到 config 默认链。
4. **WorkspaceJournal.rollbackTo 未知 marker 时 fallback 到全量恢复**（from=0），这是安全选择。
